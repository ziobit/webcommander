# Single-file asset build

The application is built from readable source files in this repository. Deploy
only `webcommander.php`; no build directory, Node.js, npm package, stylesheet,
JavaScript file, font file or CDN is needed on the server.

```sh
npm ci --prefix build --ignore-scripts
npm run build --prefix build
npm run check --prefix build
```

Edit PHP/HTML in `build/webcommander.template.php`, asset responses in
`build/assets.php`, and CSS/JavaScript in `assets/`. The runtime bootstrap
containing CSRF, root and disk information stays inline in the authenticated
HTML response; it is never part of a public cached asset.

The builder pins Terser 5.44.0 and clean-css 5.3.3 through the npm lockfile,
minifies the readable CSS/JS, and creates GZIP level 9 payloads. It retains
CodeMirror 5.65.21, Bootstrap 5.3.3, Font Awesome 6.5.2 and all previous font
bytes. CodeMirror's original readable bundle and component provenance are
preserved; the existing combined UI CSS is formatted for readability. The
original font data and source manifest are in `assets/fonts.json` and
`assets/vendor/manifest.json`. Full third-party licenses are retained in the
generated file and the packed license endpoint.

The generated PHP contains a manifest with content hashes, byte ranges, media
types and sizes. Raw packed bytes follow `__halt_compiler()`, which keeps PHP
from interpreting binary payloads. CSS/JS are stored as GZIP; WOFF2 fonts are
already compressed and are stored unchanged. This avoids Base64 expansion.
The updater's final completeness marker follows the binary pack.

Each public asset URL includes its SHA-256 version. GZIP-capable clients receive
the stored compressed bytes directly; PHP only decompresses for an identity
response. PHP zlib is needed for that fallback. Responses use a one-year public
immutable cache policy, representation-specific ETags and
`Vary: Accept-Encoding`. GET, HEAD and conditional 304 responses are supported.
Public asset requests run before session/configuration handling and do not set
cookies. Only manifest entries can be read; users cannot provide file paths or
byte ranges. Packed and decoded hashes are verified before serving a body.

Upload the generated file in binary mode. Its binary trailer must survive
unchanged; ASCII FTP transfer, newline normalization or rewriting the whole file
as UTF-8 text will corrupt it. Git marks the artifact as binary for this reason.
Its readable PHP source remains available in the template. Changes to sources
require rebuilding; the deployed file never reads development sidecar files.

Build verification compares every generated byte. Reproduce with the same
Node/zlib versions when checking an existing artifact, as GZIP output can differ
between compressor versions. This release was built with Node 24.19.0 and
zlib 1.3.2.1-motley-3246f1b; the builder reports both versions and the file hash.
It also refuses a release exceeding the configured updater cap.

```sh
node tests/assets.js
node tests/updater.js
php tests/metadata_symlinks.php
node tests/keyboard_navigation.js
```

Tests use disposable copies of the compiled file, including its binary trailer.
Asset tests cover every font/CSS/JS payload, exact GZIP transmission, identity
fallback, encoding quality, ETags/304, HEAD, server output-compression settings,
unknown versions/paths, authentication separation, corruption and truncation.
